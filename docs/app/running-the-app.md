# Building and running the mobile app

The app is an Expo SDK 58 (preview) / React Native 0.88 (RC) project living entirely in `frontend/`. It uses native modules (MapLibre Native, Skia, MMKV), so it **cannot run in Expo Go** — you build a dev client with `expo run:ios` / `expo run:android` (wrapped by the `bun run` scripts below).

## Prerequisites

| tool | version | notes |
|---|---|---|
| [Bun](https://bun.sh) | 1.4+ | replaces npm/yarn — all scripts assume `bun` |
| JDK | 17 | Gradle requirement (Android) |
| Android Studio | with API 35 SDK + emulator image | Android builds |
| Xcode | 27 (release, not beta) | iOS — deployment target is 26.0, macOS only; App Store uploads need the iOS 27 SDK from April 2027 |
| CocoaPods | 1.15+ | `gem install cocoapods` (iOS) |
| Watchman | latest | Metro file watching on macOS |

You only need the toolchain for the platform you're targeting. Linux hosts can build/run Android only.

## Run

All commands from `frontend/` — not the repo root:

```bash
cd frontend
bun install
bun start            # Metro bundler only (attach to an already-installed dev build)
bun run android      # build + install + launch on Android emulator/device
bun run ios          # build + install + launch on iOS simulator (macOS only)
```

First native build takes a while (Gradle / CocoaPods); subsequent runs are incremental.

### Radar playback kill switch

Playback mounts five raster sources and swaps their opacity, so each frame's tiles load while hidden. If that misbehaves on a device, build the old single-source variant:

```bash
EXPO_PUBLIC_CAROUSEL_WINDOW=1 bun run ios      # or: bun run android
```

`EXPO_PUBLIC_*` values are inlined when the JS bundle is built, so restart Metro with `--clear` when switching variants. Only `1` is recognised; anything else builds the 5-slot default. The checklist is in docs/reference/architecture.md § "The app".

## Android gotchas

- Use an **API 35** emulator image.
- The emulator cannot see `localhost` on your machine — reach a backend on the host via **`http://10.0.2.2:8080`** (the emulator's loopback alias).
- Predictive back gesture is deliberately disabled (it fights the bottom sheet). Don't re-enable it in `app.json` without retesting the sheet.

## iOS gotchas

- Boot a simulator first: `xcrun simctl list devices booted`
- Grant location: `xcrun simctl privacy booted grant location com.vanillax.radar-ng`
- **Never hand-edit `frontend/ios/`** — it's generated by `expo prebuild` and gitignored. Native customization goes through config plugins in `frontend/plugins/` and target sources in `frontend/targets/`.
- The CarPlay config plugin (`frontend/plugins/withCarPlayScene.js`) declares both the phone and CarPlay scenes — keep both.

## Connecting to a backend

In the app: **Settings → Advanced Mode → Stack URL**. The app has no data-source
toggle; it always talks to one stack ([self-hosting.md](../self-host/compose.md)). Enter the URL:

| where the app runs | server URL |
|---|---|
| iOS simulator (backend on same Mac) | `http://localhost:8080` |
| Android emulator | `http://10.0.2.2:8080` |
| Physical device on LAN | `http://<your-LAN-IP>:8080` |
| Public exposure | `https://radar.your-domain.example` |

The manifest fetch (`/api/manifest.json`) determines which layers the app offers, so a partially warmed-up backend just shows fewer layers until ingest catches up.

## Where preferences live

User prefs (server URL, data source, palette, opacity, playback speed, active layer, theme, extras visibility) persist in an **MMKV** store with id `radar-ng` (`frontend/src/lib/storage.ts`), read/written by `frontend/src/stores/useWeatherStore.ts`. They survive app restarts but not an uninstall. To reset to defaults, uninstall/reinstall or clear the app's storage.

## Standalone iPhone build (IPA)

A signed iPhone and iPad IPA with the Watch app embedded, that runs without Metro or EAS (macOS
and Xcode only):

```bash
cd frontend
bun run ios:ipa
```

The output lands at `artifacts/ios/export-debugging/radarng.ipa`. It's a `Release` Xcode
archive/export that embeds the JS bundle (`main.jsbundle`) and
`Payload/radarng.app/Watch/radar-ngWatch.app`, so the installed app needs no Metro server.

The default export method, `debugging`, is standalone but still development-signed with the Apple
account set up in Xcode. For a distribution-style install:

```bash
cd frontend
bun run ios:ipa:release-testing   # ad-hoc / release testing
bun run ios:ipa:app-store         # App Store Connect / TestFlight
```

`release-testing` needs the latest Apple Developer Program License Agreement accepted, an installed
Apple Distribution certificate with its private key, and provisioning profiles for both the app and
Watch bundle IDs (upstream: `com.vanillax.radar-ng` and `com.vanillax.radar-ng.watch`; forks set
their own, see [FORKING.md](../../FORKING.md)).

### TestFlight from CI

If a self-hosted Mac runner is set up, the `build · ios` workflow can upload straight to TestFlight:

```bash
gh workflow run build-ios.yml --ref master -f scheme=radarng -f testflight=true
```

This needs the app record in App Store Connect and an App Store Connect API key on the Mac with at
least the App Manager role. The build then appears in the TestFlight app for internal testers.
Without `testflight=true`, the run attaches the IPA as an `ipa` artifact instead.

## iOS extras: CarPlay + Apple Watch

The repo ships a native Watch radar/forecast app and an experimental CarPlay map
scene. Watch uses normal development signing. A full CarPlay map requires Apple's
navigation entitlement and matching provisioning; post-archive re-signing does not
bypass that requirement. A CarPlay radar widget is planned separately.

Build and test instructions: [carplay-watch-setup.md](carplay-watch-setup.md).
