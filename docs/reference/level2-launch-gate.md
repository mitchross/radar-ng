[#293](https://github.com/mitchross/radar-ng/issues/293). Design:
[level2-close-up.md](../develop/design/level2-close-up.md). Enable and disable steps:
[level2-enable-disable.md](../self-host/level2-enable-disable.md).

stub results do not go here.

## 6. Remaining risks

Keep the known ones and add what the run found. Each line says what would show it and what the
operator does.

| Risk | How it would show | Response |
|---|---|---|
| `LEVEL2_ENABLED_STATIONS` unset defaults to `KGRR` | KGRR enabled where nobody chose it | every manifest sets it explicitly; check `enabled_regions` in `/api/level2/sites` after each change |
| NOAA chunk feed stalls or lags for a station | `RadarNgLevel2FeedStale`; station `late` | automatic MRMS fallback; nothing to do unless it persists, then disable that station |
| RustFS is outside the cluster | tile 503s, `RadarNgLevel2CacheNearCap`, evictions failing | automatic fallback; check RustFS; disable Level II if it lasts |
| Temporal restart longer than one cadence | schedule-to-start over the cadence | MRMS catches up; Level II goes `late` then recovers |
| Pool caps (8 stations, 2 decodes) reached in a busy outbreak | `saturated` fallbacks | by design: MRMS for the extra stations; raise caps only after measured RSS allows |
| Residual clutter or QC artefacts the review did not cover | user reports, review findings | disable the station; QC change goes through a new review |
| `release-env-patch.yaml` rolls the Level II pool with MRMS env changes | pool restarts on MRMS releases | harmless; the restart drill covers it |
| _found during the run_ | | |
