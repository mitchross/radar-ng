Read this whole file before changing anything under `rust/`, `deploy/Dockerfile` or
`.github/workflows/ci-rust.yml` / `ghcr-*.yml`. History and the reasons behind these rules:
`docs/develop/rust-backend-handoff.md`. Crate map and env vars: `rust/README.md` and
`rust/crates/<crate>/README.md`.

## 1. Toolchain

- Rust **1.97.0**, pinned in `rust/rust-toolchain.toml` (with clippy and rustfmt). rustup installs it
  automatically. **Never bump it in passing**: CI, the Docker builder and local builds share it so
  clippy sees the same lints everywhere. A bump is its own PR.
- The Temporal SDK build needs **`protoc` plus the well-known types**: `protobuf-compiler` and
  `libprotobuf-dev` on Debian/Ubuntu, `protobuf` on Arch/CachyOS, `brew install protobuf` on macOS.
- **Resources:** a full `cargo build --release` or `cargo test --workspace` needs several GB in
  `target/` and a lot of RAM. Run it on a real machine, not a small agent container. Put
  `CARGO_TARGET_DIR` on a big disk if the repo's disk is small. If you can't build, say so; don't
  claim the gate passed.

## 2. The gate before any push (run in `rust/`)

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

All three must pass. `cargo test` includes the offline Temporal **replay gate**
(`crates/radar-worker/tests/replay.rs`), which also runs inside the worker image build. CI
(`ci-rust.yml`) additionally runs `temporal` (integration tests against a real server), `live-noaa`
and `images`.

## 3. Temporal replay compatibility (the easiest thing to break)

- Every recorded history in `crates/radar-worker/testdata/replay_fixtures` must keep replaying on the
  current workflows. These were recorded from the old Python workers; there is **no generator for
  Rust-recorded histories yet**.
- **Don't reorder, add or remove workflow commands** (activities, timers, child workflows, signals)
  without running `cargo test -p radar-worker --test replay`. If a change is intentionally
  incompatible, it needs worker versioning, not a fixture edit.
- `ctx.timer()` schedules the timer immediately; a timer you stop waiting on must be **cancelled
  explicitly**.
- Workflow and activity names, task queues, schedule IDs and payload shapes are a wire contract.
  They live in `crates/radar-types`; change them only deliberately.

## 4. Concurrency traps

- `radar_tiler::render_frame_palettes` holds a file lock while rendering on Rayon. Calling it from
  **parallel tasks on one Rayon pool deadlocks** (nowcast did this until #97). Call it from a plain
  thread, or one frame at a time.
- When a Temporal activity **times out, its `spawn_blocking` render keeps running** and holds memory
  across retries. Keep blocking work bounded; don't assume a timeout freed anything.
- Long CPU work must keep heartbeating from the async side (`radar_core::heartbeat`).

## 5. Drop-in image contract (`deploy/Dockerfile`)

Existing deployments don't change when the image does, so keep: the ports (api 8080), uids **1000**
(api, worker) and **999** (open-meteo), probe files **`/tmp/worker-alive`** and
**`/tmp/temporal-healthy`**, and busybox `sh`, `find`, `test` for the exec probes. Liveness for the
api is `/api/livez`; `/api/health` is a data-freshness check that returns 503 when radar is stale.
The `images` CI job checks this contract.

## 6. GRIB quirks (`radar-grib`)

- MRMS sets template 3.0 **basic angle 1 with 10^6 subdivisions** (synthetic fixtures used 0).
- HRRR precip-type codes come as WMO **0.1.33–36** *and* NCEP-local **0.1.192–195**; accept both.
- HRRR leaves the surface (type 1) value missing; treat missing as 0.
- Golden fixtures were generated by the old Python code (`testdata/gen_*.py`); to regenerate one,
  check out commit `5b3cb39`.
- Before claiming a GRIB or render change works on real data, run `rust/scripts/live-noaa-check.sh`
  (downloads the newest MRMS and HRRR files and renders them).

## 7. Releases

Merging to `master` publishes the next `ghcr.io/<owner>/radar-ng-*:vX.Y.Z` (`ghcr-backend.yml`).
Deployments pin tag **and** digest, never `latest`. Releases are **forward-only**: fix a bad release
with a new one. Upstream's own deploy flow is in `AGENTS.md` → "Upstream maintainer only".
